## 0. 조사 제약과 전제

기획에 앞서 한계를 명시한다. 참고 사이트 `insurancesalon.qshop.ai` 는 현재 작업 환경의 **네트워크 egress 정책에 의해 차단(CONNECT 403)** 되어 직접 열람하지 못했다. `qshop.ai` 본 도메인과 동일 계열 서브도메인 역시 동일하게 차단되어, 화면을 눈으로 확인한 상태가 아니다.

대신 검색으로 확인한 사실은 다음과 같다.

| 확인 항목 | 내용 |
| --- | --- |
| 플랫폼 | qshop.ai — 코드 없이 사이트를 만드는 국내 AI 홈페이지 빌더 |
| 구성 단위 | 헤더 / 바디 / 푸터 영역을 **섹션** 단위로 쌓는 구조. 빈섹션·상품목록·슬라이더·탭 섹션 제공 |
| 편집 단위 | 섹션 안에 텍스트·미디어·아이콘·상품 **블록**을 배치 |
| 동종 사례 | `hamdah.qshop.ai`(보험관리자), `mz-insure.qshop.ai`(펫보험), `hi-insure.qshop.ai`(간병인보험), `aplus-aaa.qshop.ai` 등 보험 상담·모집 랜딩이 다수 |

이 단서를 종합하면 벤치마크는 **세로로 길게 스크롤되는 원페이지 랜딩 + 하단 고정 CTA + 상담신청 폼**으로 리드를 받는, 국내 보험·금융 상담 사이트의 전형적 포맷이다. 본 기획안은 이 포맷을 전제로 작성했다.

**전제가 틀릴 경우 조정 범위**는 5장(화면 설계)의 섹션 순서와 9장(구현 방식)에 한정된다. 2~4장의 메시지·타깃 정의와 6장 이후의 리드 설계·법적 검토·운영 계획은 벤치마크 구조와 무관하게 그대로 유효하다. 참고 사이트에 접근 가능한 환경에서 캡처본을 주시면 5장을 실제 섹션 순서에 맞춰 즉시 교정하겠다.

> **기존 문서와의 관계** — 저장소의 `docs/website-plan.md` 는 하랑솔루션을 B2B 소프트웨어 솔루션 기업으로 가정하고 작성된 문서로, 실제 사업 정의와 맞지 않는다. 본 문서가 이를 대체한다.

## 1. 프로젝트 개요

### 1.1 배경

하랑솔루션은 정책자금 중개사로 오해받기 쉬운 위치에 있다. 실제로는 **자금 조달부터 절세·법인전환·대표자 자산·사업장 안전관리까지 대표의 돈의 흐름 전체를 진단하고, 분야별 전문가 실행을 연결하는 컨설팅 회사**다.

이 간극이 지금의 가장 큰 사업적 손실이다. "정책자금 되나요?"라는 단발성 문의만 들어오고, 그 뒤에 있는 절세·법인전환·대표자 자산관리라는 장기 관계형 수익으로 이어지지 않는다.

홈페이지의 역할은 명확하다. **첫 접촉 시점에 "이 회사는 자금만 보는 곳이 아니다"를 각인시키고, 진단 상담으로 넘기는 것.**

### 1.2 목적

| 순위 | 목적 | 측정 방법 |
| --- | --- | --- |
| 1 | 상담·문의 리드 수집 | 폼 제출 + 전화·카톡 클릭 수 |
| 2 | 사업 범위 인식 전환 (자금 전문 → 돈의 흐름 전체) | 폼의 '관심 영역' 복수 선택 비율 |
| 3 | 상담 전 신뢰 형성 | 폼 도달률, 체류시간, FAQ 열람률 |
| 4 | 유효 리드 선별 | 상담신청 대비 1차 미팅 전환율 |

### 1.3 범위

| 구분 | 포함 | 제외 |
| --- | --- | --- |
| 사이트 | 국문 원페이지 랜딩 1본, 법적 고지 페이지 2종(개인정보처리방침·이용약관) | 블로그/뉴스 게시판(2차), 회원 로그인, 고객 포털 |
| 콘텐츠 | 전 섹션 카피, 상담 사례 6건, FAQ 12문항 | 대표 인터뷰 영상, 현장 촬영 |
| 기능 | 상담신청 폼, 리드 알림, 전화·카톡 연결, 방문 분석 | CRM 자동 연동(2차), 결제 |
| 검토 | 금융·보험 광고 규제 사전 점검, 개인정보 동의 설계 | 실제 인허가 취득 대행 |

### 1.4 성공 지표 (오픈 6개월 기준)

| 지표 | 목표 |
| --- | --- |
| 월간 순 방문자 | 2,000명 |
| 월간 상담신청 폼 제출 | 40건 |
| 폼 전환율 (방문 → 제출) | 2.0% 이상 |
| 전화·카톡 클릭 포함 총 리드 | 월 70건 |
| 유효 리드 비율 (1차 미팅 성사) | 40% 이상 |
| 복수 관심영역 선택 비율 | 50% 이상 *(인식 전환의 실질 지표)* |
| 모바일 트래픽 비중 | 70% 이상 *(모바일 우선 설계의 근거)* |

> 마지막 두 지표가 이 사이트의 성패를 가른다. 폼 제출 수만 보면 "정책자금 하나만 묻는 리드"가 늘어도 성공으로 보이기 때문이다.

## 2. 브랜드 메시지 설계

### 2.1 핵심 메시지

> **매출보다 중요한 건, 돈의 흐름입니다.**

이 한 문장이 히어로 영역의 H1이자 사이트 전체의 뼈대다. 아래 네 동사가 모든 섹션의 배열 기준이 된다.

| 단계 | 동사 | 대응 사업 영역 |
| --- | --- | --- |
| 조달 | 어떻게 조달하고 | 정책자금·기업자금 / 사업자·기업·부동산 대출 |
| 방어 | 어떻게 지키고 | 사업장 안전관리(중대재해처벌법) / 기업 리스크 |
| 보존 | 어떻게 남기고 | 절세·법인전환 / 기업 인증·특허 |
| 증식 | 어떻게 대표자 자산으로 만들지 | 대표자 퇴직재원·연금·상속·가업승계 |

6개 사업 영역을 나열식으로 보여주면 "이것저것 다 하는 회사"가 된다. **조달–방어–보존–증식의 흐름에 얹으면 "순서를 아는 회사"가 된다.** 이 차이가 기획의 핵심이며, 정보구조 전체를 이 4단계로 잡는다.

### 2.2 포지셔닝 — 아닌 것부터 말한다

사이트 상단에서 다음을 명시적으로 부정한다. 동종 업계의 난립한 광고와 구별되는 가장 빠른 방법이다.

- 정책자금만 하는 회사가 아닙니다
- 보험만 파는 회사가 아닙니다
- 대출만 연결하는 회사가 아닙니다
- 법인전환만 권하는 회사가 아닙니다

→ **대표님의 사업과 돈 전체를 같이 보는 회사입니다.**

### 2.3 상담 4원칙 (신뢰 섹션의 본문)

1. 무조건 된다고 하지 않습니다.
2. 되는 것과 어려운 것을 구분해 알려드립니다.
3. 지금 당장 필요 없는 건, 하지 마시라고 말씀드립니다.
4. 한 번의 계약보다 오래 가는 관계를 만듭니다.

이 4원칙은 **광고 규제 리스크를 낮추는 장치이기도 하다.** "100% 승인" 류의 확정적 표현이 만연한 시장에서, 확정을 하지 않겠다는 선언 자체가 차별화이자 표시광고법 방어선이 된다(10장 참조).

### 2.4 톤앤매너

| 항목 | 방향 | 금지 |
| --- | --- | --- |
| 화법 | 대표님을 마주 앉아 설명하는 어조. 단문. | 과장 감탄사, 이모지 남발 |
| 숫자 | 실제 확인 가능한 수치만 | "최대 5억"처럼 조건을 숨긴 상한선 강조 |
| 확정성 | "검토합니다", "가능 여부를 봅니다" | "됩니다", "보장", "100%" |
| 전문용어 | 처음 나올 때 한 줄 풀이 병기 | 기관명 약어 나열 |

## 3. 타깃 정의

### 3.1 1차 타깃 — 개인사업자 대표 (제조업 중심)

매출 규모가 커지면서 세금과 자금이 동시에 문제가 되기 시작한 구간의 대표. 연 매출 10억 내외, 상시근로자 5인 이상이 특히 핵심이다. 안전관리 의무까지 한꺼번에 얹히는 시점이기 때문이다.

이들이 사이트에서 찾는 것: **"내 상황에서 뭐부터 해야 하는지"**. 상품 설명이 아니다.

### 3.2 진입 고민 유형 (섹션 2의 체크리스트 원문이 된다)

- 매출은 늘었는데 세금 부담이 커졌다
- 운영자금·시설자금이 필요하다
- 은행 대출과 정책자금 중 뭘 먼저 봐야 할지 모르겠다
- 개인사업자를 유지할지 법인전환을 할지 고민이다
- 돈은 버는데 대표 개인 자산은 안 쌓인다
- 직원이 늘어 사업장 안전관리까지 챙겨야 한다
- 퇴직금·연금·보험·노후 준비를 못 하고 있다

### 3.3 업종별 비중

| 업종 | 비중 | 랜딩 카피 강조점 |
| --- | --- | --- |
| 제조업 | 최우선 | 시설자금, 기술보증기금, 특허·기업부설연구소, 중대재해처벌법 |
| 음식점 | 보조 | 소상공인시장진흥공단, 운영자금, 신용보증재단 |
| 도소매·서비스업 | 보조 | 운영자금, 신용보증기금, 절세 |
| 스크린골프장 등 시설업 | 보조 | 시설자금, 부동산담보대출 |

제조업 대표에게는 "대표님이 당연하게 여기는 공정·생산방법·품질개선 노하우가 특허와 인증 소재가 될 수 있다"는 메시지가 가장 강하게 작동한다. 5장 섹션 5에 이 문장을 그대로 쓴다.

## 4. 벤치마크 구조 분석

### 4.1 상담형 원페이지 랜딩의 전형 구조

qshop.ai 계열 보험·금융 상담 사이트는 다음 순서를 공유한다.

```
① 헤더(로고 + 전화 버튼)
② 히어로 — 강한 한 문장 + CTA
③ 신뢰 지표 바 — 숫자 3~4개
④ 문제 제기 — "이런 고민 있으신가요"
⑤ 서비스 카드
⑥ 차별점 / 왜 우리인가
⑦ 프로세스 스텝
⑧ 사례 · 후기
⑨ FAQ 아코디언
⑩ 상담신청 폼
⑪ 푸터(사업자 정보)
⑫ 모바일 하단 고정 CTA 바
```

### 4.2 그대로 가져올 것

- **원페이지 + 하단 고정 CTA.** 메뉴를 돌아다니게 하지 않고 스크롤 한 방향으로 폼까지 밀어 넣는 구조. 리드 수집이 1순위 목표인 이상 이 구조가 정답이다.
- **모바일 우선.** 이 카테고리의 트래픽은 대부분 모바일이다. 데스크톱은 모바일 레이아웃의 확장으로 설계한다.
- **문제 제기를 서비스 소개보다 앞에 두는 순서.**

### 4.3 바꿀 것

| 벤치마크의 한계 | 하랑솔루션 적용안 |
| --- | --- |
| 서비스 카드가 나열식 | 조달–방어–보존–증식 4단계 흐름에 얹어 배치 (2.1) |
| 단일 상품 랜딩이라 관심영역 분기가 없음 | 폼에 관심 영역 복수 선택을 넣어 리드를 분류 |
| 후기가 감정 위주 | "무엇을 어떤 순서로 실행했는가" 중심의 사례로 전환 |
| 확정적 표현 다수 | 4원칙 기반의 비확정 화법 (2.3, 10장) |
| 제3자 제공 동의 설계 취약 | 파트너 연계가 사업 구조의 핵심이므로 동의 항목을 분리 설계 (6.3) |

## 5. 화면 설계 — 섹션별 상세

원페이지. 섹션 번호는 스크롤 순서다. 각 섹션의 카피는 **바로 쓸 수 있는 초안**으로 작성했다.

### 섹션 0 · 헤더 (스크롤 고정)

- 좌: 하랑솔루션 로고
- 우: `전화상담` 버튼 (tel: 링크), 모바일에서는 아이콘만
- 배경: 스크롤 시 반투명 → 불투명 전환
- 높이: 모바일 56px / 데스크톱 72px

### 섹션 1 · 히어로

```
[배경: 어두운 네이비 그라데이션 + 서류·미팅 이미지 오버레이]

매출보다 중요한 건,
돈의 흐름입니다.

사업에서 번 돈을
어떻게 조달하고, 어떻게 지키고,
어떻게 남기고, 어떻게 대표님의 자산으로 만들지까지.

[ 무료 진단 상담 신청 ]   [ 전화로 바로 상담 ]
```

- H1은 2줄 고정 개행. 모바일에서도 줄바꿈 위치를 유지한다.
- 1차 CTA는 폼으로 스크롤 이동, 2차는 전화 연결.
- **첫 화면에서 CTA가 반드시 보여야 한다.** 모바일 뷰포트 높이 기준으로 검수한다.

### 섹션 2 · 문제 제기 — "혹시 이런 고민, 하고 계신가요?"

3.2의 7개 항목을 체크리스트 카드로. 모바일 1열, 데스크톱 2열.

각 항목 앞에 체크 아이콘. 하단에 연결 문장:

> 하나라도 해당되신다면, 지금 필요한 건 상품 설명이 아니라 **순서 정리**입니다.

### 섹션 3 · 접근 방식 — "하랑솔루션은 이렇게 봅니다"

2.1의 4단계를 가로 흐름 다이어그램으로. 모바일은 세로 스택.

```
조달 → 방어 → 보존 → 증식

조달  어떻게 조달할 것인가    정책자금 · 기업자금 · 대출
방어  어떻게 지킬 것인가      사업장 안전관리 · 기업 리스크
```

## 6. 리드 수집 설계

리드 수집이 1순위 목표이므로 폼 설계를 별도 장으로 다룬다.

### 6.1 입력 항목

| 항목 | 유형 | 필수 | 비고 |
| --- | --- | --- | --- |
| 성함 | 텍스트 | ● | |
| 연락처 | 숫자 키패드 | ● | 자동 하이픈, 010 형식 검증 |
| 업종 | 선택 | ● | 제조업 / 음식점 / 도소매 / 서비스업 / 시설업 / 기타 |
| 연 매출 규모 | 선택 | ○ | 3억 미만 / 3~10억 / 10~30억 / 30억 이상 |
| 관심 영역 | **복수 선택** | ● | 자금조달 / 대출 / 절세·법인전환 / 대표자 자산 / 인증·특허 / 안전관리 / 아직 모르겠다 |
| 상담 희망 시간대 | 선택 | ○ | 오전 / 오후 / 저녁 / 무관 |
| 문의 내용 | 텍스트영역 | ○ | placeholder: "지금 가장 큰 고민을 한 줄만 적어주세요" |

**필수는 4개만.** 필수 항목이 늘수록 전환율은 직선으로 떨어진다. '연 매출'과 '희망 시간대'는 선택으로 두되, 입력되면 리드 우선순위 산정에 쓴다.

**'관심 영역' 복수 선택은 이 폼의 전략적 핵심이다.** 선택지를 보는 것만으로 "이 회사가 이만큼을 본다"는 메시지가 전달되고, 선택 결과가 그대로 성공 지표(1.4)가 된다. `아직 모르겠다` 항목을 반드시 넣는다 — 진입 장벽을 없애고, 오히려 진단형 상담에 가장 적합한 리드다.

### 6.2 동의 항목 (분리 필수)

| 동의 | 필수 여부 | 문구 요지 |
| --- | --- | --- |
| 개인정보 수집·이용 | 필수 | 수집 항목 / 이용 목적(상담 제공) / 보유기간(상담 종료 후 O년) |
| **개인정보 제3자 제공** | 필수 또는 선택 | 제공받는 자(파트너사 실명), 제공 항목, 제공 목적, 보유기간 |
| 마케팅 정보 수신 | **선택** | 동의하지 않아도 상담은 진행됨을 명시 |

세 건을 **한 개의 체크박스로 묶으면 안 된다.** 특히 제3자 제공은 하랑솔루션 사업 구조의 핵심(파트너 연계)이면서 동시에 가장 흔한 위반 지점이다. 각 항목 옆에 전문 보기(모달)를 둔다.

제3자 제공을 필수로 둘지 선택으로 둘지는 법률 검토 사항이다. 상담 제공에 필수불가결하지 않다면 선택으로 두어야 한다.

### 6.3 제출 후 처리

```
제출
 ├─ 담당자 즉시 알림      카카오 알림톡 or SMS (30초 내)
 ├─ 신청자 접수 확인      "OO 담당자가 O시간 내 연락드립니다"
 ├─ 스프레드시트 적재     일시 / 유입경로 / 관심영역 / 우선순위
 └─ 전환 이벤트 기록      GA4 + 광고 픽셀
```

- **응답 속도가 전환율을 좌우한다.** 리드 알림은 이메일이 아니라 알림톡으로 받는다.
- 완료 화면은 새 페이지가 아니라 폼 자리의 인라인 전환으로 처리하되, GA4 전환 이벤트는 반드시 발화시킨다.

### 6.4 스팸·허수 대응

- reCAPTCHA v3 (체크박스 없는 점수 기반 — 전환율 손실 최소화)
- 동일 연락처 24시간 내 중복 제출 차단

| Accent | `#C9A227` 골드 | CTA 버튼, 핵심 수치 — **전체 면적의 5% 이내** |
| Background | `#F7F8FA` | 섹션 교차 배경 |
| Surface | `#FFFFFF` | 카드 |
| Text | `#1A1A1A` / `#5B6472` | 본문 / 보조 |
| Line | `#E3E6EB` | 구분선 |

CTA 골드는 히어로 버튼, 고정 바 버튼, 폼 제출 버튼 **세 곳에만** 쓴다. 다른 곳에 쓰는 순간 CTA가 눈에 띄지 않게 된다.

### 8.3 타이포그래피

Pretendard.

| 스타일 | 모바일 / 데스크톱 | 두께 |
| --- | --- | --- |
| H1 (히어로) | 30px / 52px | 700 |
| H2 (섹션 제목) | 24px / 38px | 700 |
| H3 (카드 제목) | 18px / 22px | 600 |
| 본문 | 16px / 17px | 400, 행간 1.7 |
| 보조 | 14px | 400 |

본문 16px 미만 금지. 1차 타깃 연령대를 고려한다.

### 8.4 컴포넌트

- 카드: radius 12px, 테두리 1px `#E3E6EB`, 그림자 없음 또는 `0 1px 3px rgba(0,0,0,.05)`
- 버튼: 높이 모바일 52px, 터치 타깃 최소 44×44px
- 섹션 패딩: 모바일 64px / 데스크톱 120px (상하)
- 최대 폭: 1140px
- 모바일 좌우 여백: 20px

### 8.5 접근성

- 본문 대비비 4.5:1 이상. **골드(`#C9A227`) 위 흰 글씨는 대비 미달이므로 CTA 버튼 텍스트는 `#10243E`(딥네이비)로 한다.**
- 모든 이미지에 대체 텍스트
- 폼 라벨을 placeholder로 대체하지 않는다 — 입력 중 라벨이 사라지면 안 된다
- 키보드 포커스 표시 유지

## 9. 구현 방식

### 9.1 두 가지 안

| 항목 | A안 · qshop.ai 그대로 | B안 · 자체 구축 (Next.js) |
| --- | --- | --- |
| 오픈까지 | 2~3주 | 6~8주 |
| 초기 비용 | 낮음 | 높음 |
| 운영 | 비개발자 직접 수정 가능 | 개발 리소스 필요 |
| 도메인 | 커스텀 도메인 연결 가능 여부 확인 필요 | 자유 |
| 폼·알림톡 | 플랫폼 제공 기능 범위 내 | 자유 설계 |
| 광고 전환 태그 | 삽입 가능 여부 확인 필요 | 자유 |
| SEO | 제한적 | 우수 |
| 확장(블로그·사례 DB) | 제한적 | 자유 |

### 9.2 권고

**A안으로 시작한다.** 근거는 세 가지다.

1. 1순위 목표가 리드 수집이고, 리드는 광고 유입에서 나온다. SEO 우위가 당장의 KPI에 기여하지 않는다.
2. 원페이지 랜딩은 **카피와 순서를 빠르게 고쳐가며 최적화하는 것**이 성패를 가른다. 비개발자가 직접 수정할 수 있는 편이 낫다.
3. 벤치마크가 같은 플랫폼이므로 구조 재현 리스크가 가장 낮다.

단, 계약 전 다음 세 가지를 반드시 확인한다. 하나라도 불가하면 B안으로 전환한다.

- [ ] 커스텀 도메인 연결 및 HTTPS 지원
- [ ] `<head>` 스크립트 삽입 (GA4, 네이버·구글 광고 전환 태그)
- [ ] 폼 제출 데이터의 외부 연동(웹훅 또는 최소한 CSV 내보내기)

### 9.3 2단계 확장 (오픈 6개월 후)

상담 사례와 칼럼이 30건 이상 쌓이면 검색 유입이 유의미해진다. 이 시점에 B안으로 이관하고, 랜딩은 그대로 유지한 채 `/cases`, `/column` 을 붙인다.

### 9.4 성능 목표

| 지표 | 목표 |
| --- | --- |
| LCP (모바일 4G) | 2.5초 이하 |
| 총 이미지 용량 | 1.5MB 이하 |
| 이미지 포맷 | WebP, 지연 로딩 |

광고로 들어온 사용자는 3초를 기다리지 않는다. 히어로 배경 이미지 최적화가 가장 큰 변수다.

## 부록 A. 히어로 카피 대안 3종

A/B 테스트용. 13.2의 개선 루프에서 순차 검증한다.

| 안 | H1 | 성격 |
| --- | --- | --- |
| A (기본) | 매출보다 중요한 건, 돈의 흐름입니다 | 브랜드 메시지형 |
| B | 지금 대표님께 필요한 건, 상품이 아니라 순서입니다 | 문제 제기형 |
| C | 조달하고, 지키고, 남기고, 키웁니다 | 서비스 요약형 |

A를 기본으로 오픈하고, 광고 유입 전환율이 목표에 미달하면 B를 시험한다. B는 클릭 후 이탈이 많은 경우(기대 불일치)에 특히 유효하다.

## 부록 B. 폼 '관심 영역' 선택지와 내부 라우팅

| 선택지 | 1차 담당 | 연계 파트너 |
| --- | --- | --- |
| 자금조달 | 하랑솔루션 | 하랑파트너스 |
| 대출 | 하랑솔루션 | C&U파트너스 |
| 절세·법인전환 | 하랑솔루션 | 세무·법무 네트워크 |
| 대표자 자산 | 하랑솔루션 | 키움에셋플래너 / 한국투자증권 |
| 인증·특허 | 하랑솔루션 | 하랑파트너스 |
| 안전관리 | 하랑솔루션 | 안전ON |
| 아직 모르겠다 | 하랑솔루션 (진단 상담) | — |

모든 리드의 1차 접점은 하랑솔루션이다. 파트너로 바로 넘기지 않는다. 이것이 7번(파트너 네트워크)과 8번(상담 프로세스)에서 약속한 구조이며, 지속관리 수익 구조의 전제다.
